## 1. 券商组织学调研的核心发现 → 系统映射

调研五结论（详见 research 稿）：①首席定基调不动笔，**助理"在家攒数据"写最多**；②资深拿到的是**结构化中间产物**不是原始数据；③**事件点评快的秘密 = 模型常备+增量更新**（财报季 associate 早 7 点听会 9 点前发 2 页 note），不是人多；④质控+合规两轮、署名负法定责任；⑤**超短对照（游资复盘）是单人全流程**，公开资料找不到"龙虎榜归 A、题材归 B"的团队分工。

| 券商角色/机制 | 现系统对应 | 状态 |
|---|---|---|
| 助理维护模型/数据库 | 湖 + harvest/slim/因子表（零 LLM） | ✅ 已有 |
| 行业研究员 / 策略师晨会 | sector-brief（TTL 复用）/ macro-brief market_view | ✅ 已有 |
| 事件点评快 = 模型常备+增量 | 档案前科卡 + ♻️复用 + "变化项 vs 档案" | ✅ 已有 |
| 质控/合规两轮 | self_review lint + 契约门 + 买单 ensemble | ✅ 已有 |
| **助理盯公告/新闻写 flash note** | **卡内 ≤5 条网查——由最贵的 xhigh Opus 自己做** | ❌ 唯一真缺口 → 本稿 |
| 首席判断+署名 | l4-card 单脑 Opus | 保持（游资单人全流程对照 + B12 电话效应都支持单脑） |

**刻度校正**：券商一组 4–5 人是摊在几十只票上的常备状态维护编制；落到"某票某日出一篇点评"，边际投入 = 1 个助理增量更新 + 首席复核——正是本稿形状（1 情报员 + 1 分析员）。

## 2. 择向记录：乙（情报站）vs 丙（全面 fan-out）

用户初始构想偏丙（每票 4–5 个面 searcher 并发 + 高 effort 综合）；对撞后用户澄清真实意图 = **乙的形状**（情报预取 ready → 单 Opus 分析）。对撞要点存档：

- **七维对撞**：信息增量（丙多出的面恰是账本/文献判过低值的：席位 A8 胜率不过半、日度主力 A11 不显著、情绪源不可达）/ 合成风险（B12 电话效应、B13 叙事过载随笔记数上升）/ 成本（丙 ×4–5，每天多几百次网查）/ 墙钟（180 agent 过 ~14 并发槽：L4 段 ~14m→~30m+，变慢不变快）/ 工程缝隙（**5 个新生产者 vs 1 个**——本仓最高发 bug 类 = 生产者没接进真调用链，FN-1 连修五次）/ 可证伪性（5 变量一次上无法归因，单变量 config on/off 干净 A/B）/ 升级路径（乙→丙 可分期且每步带归因）。
- **丙的空转岗位论**：资金/财务/席位面的数字，tushare 湖比任何 web searcher 又准又免费——给这些面配 searcher，只能复述 slim（纯损耗）或网查更差数字（负价值）。真正必须活体网查的只有事件/题材/机构观点一簇，一个通才 agent ≤6–8 条搜索装得下。
- **丙独有的三样 + 更便宜的获取方式**：题材专家读法→**市场级题材 pack**（一天一张服务全部票，见触发器 A）；按发现自适应加深→**survivor 升级段**（每天 0–5 只，见触发器 B）；面专家 prompt 深度→账本证明 intel 某面系统性偏薄再拆。
- **拍板：乙为骨架，丙按账本分期移植**；丙完整形态保留给 stock-research full 档（首次覆盖模式，广度是产品、量 1–2 次/天）。

## 3. 设计 · 情报员（`l4-intel`，sonnet·low，每票一个）

**原则**：凡湖里有确定性源的一律不查（行情/资金流/财务/估值/质押/解禁/户数/预告快报——网查只会更差）；只查必须活体网络的一簇。按 T+2 价值排序：

| # | 情报面 | 查什么 | 对应券商实务 | 为什么湖里没有 |
|---|---|---|---|---|
| 1 | 公告增量+正文解读 | 近 5 交易日新公告正文级含义：重组/中标/合同（金额量级）/回购增减持/预告修正/停复牌/问询函回复 | 助理"公告跟踪"、事件点评起点 | anns 端点只有标题 |
| 2 | 突发新闻 | 近 3–5 日本票新闻（尤其分析日盘后）；点名本票的产业链价格异动 | 晨会"隔夜要闻" | 湖 feed 有滞后与缺口 |
| 3 | 题材归属+梯队位置 | 归入什么概念/是否当前主线/龙跟蹭位置/同题材今日涨停家数 | 游资"涨停复盘题材归类" | 题材图谱是纯市场叙事无结构化源 |
| 4 | 卖方/机构动向 | 近 1 月研报家数与方向/目标价区间变化/调研纪要动向 | 案头"同业券商报告" | 替代现卡内 ≤2 条机构面网查 |
| 5 | 互动易/e互动 | 近 1 周公司对热点问题的回复（题材发酵火种） | 游资实务重要源（券商调研未提） | A股特色源无 API |
| 6 | 负面增量 | 立案/警示函/媒体质疑的新闻级增量 | 风险监控 | reg_flag 是检测器，新闻是前哨 |

**输入（防污染，B1/B2）**：只给 代码/名称/行业/主营一句/分析日 + **slim 新闻节已知事件标题清单**（增量定向，档案哲学同构）。**不给** L3 论点/conviction/lane/任何评分——盲搜使查询不被假设带偏（比现状干净：今天是卡 agent 先形成假设再搜，查询天然确认偏误形状）。

**输出契约** `context/scan/<date>/_l4_intel_<code>.md`（B13 事件行范式）：

```
## 事件段(≤8行)   | 日期 | 事件一行 | 源 | 2日内可发酵? | 净分(−2..+2) |
## 题材段(≤3行)   归属/是否主线/梯队位置/同题材今日强度
## 机构段(≤3行)   研报家数方向/目标价区间/调研动向(presence-gated)
## 互动段(≤2行) · 负面增量段(≤2行)
## 声明行   网查N条 | 无重大事件直说 | as-of≤分析日 | 未覆盖面标「未查」
```

铁律全继承：日期必落/来源必落/未来日期丢弃（前视 lint 对 intel 文件同样机检，B15）/找不到写"无"不硬编/搜索预算 ≤6–8 条/只报本票事实不喊单。

## 4. 设计 · 分析员（l4-card 不加维，4 个既有维换实弹）

判断骨架不动（P1 波刚重锚，动了没法验收）。intel 的作用：

| 分析维 | 现状窘境 | intel 到位后 | 对应券商分析 |
|---|---|---|---|
| P3 催化核 | 自搜 ≤3 条，常"无重大事件" | **事件×发酵分析**：新鲜度→已 price-in 多少（事件日至今涨幅 vs 量级）→发酵路径（题材共振/独立） | 事件点评"事件→影响→预期差" |
| 兑现机制维（07-11 新增） | "明天谁来买"靠推测 | 题材段作答：主线跟风位=接力盘；无题材=2 日兑现概率低 | 游资梯队/情绪位置研判 |
| P5 预期差 | 常"跟随共识无 alpha"——不知共识是什么 | 机构段给共识锚（研报方向/目标价区间） | "与市场预期对比"本职 |
| 变化项(vs 档案) | 只有湖数据可比 | 公告增量+互动易回复进增量清单 | 助理"模型常备+增量更新" |

**流程唯一改动**：P3 从"自发 ≤3 条网查"改为"**读 intel 文件 + ≤1 条验证网查**"（intel 与 slim 矛盾时用）；P4 机构面网查取消、改读机构段。**缺 intel 文件 → 回退现行卡内网查**（presence-gated，parity 不破）。防误杀铁律不变：催化（=intel 事件段）读完才许早停。

## 5. 数据流全图

```
确定性层(不变): 湖 → slim/deep + 简报(L1画像/中性前提/📐基率/席位/质押/日历/档案)
新增并行段:     l4-intel (sonnet·low·盲于L3) ──→ _l4_intel_<code>.md   [与 slim harvest 同窗口(~10m),不占关键路径]
分析层(不变):   l4-card (opus·xhigh) P0→P1盲读→P2→P3(读intel)→早停②→P4(deep+机构段)→P5 → ensemble(≥OW)
```

成本量级：+11~30 个小 Sonnet 会话/日（输入以搜索结果为主 ~20–40k/个），抵扣项 = 同样的搜索结果不再进 xhigh Opus context（~5× 价差）≈ **打平或微增**；墙钟省掉卡内 3–5 次串行搜索延迟，intel 塞进 harvest 窗口 ≈ 全链不变。

## 7. 预注册升级触发器（现在写死，免得将来重吵）
