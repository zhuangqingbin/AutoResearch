# 研究深度升级:券商级常备覆盖档案体系(design)

> 2026-07-22 · brainstorm 定稿。起因:07-21 崩盘后 V 反日扫描,用户对报告"研究丰富度/准确度"不满(卡薄:半数卡 80~110s 早停、带日期引用最少 4 行;叠加空 config 事故 intel 全关,fb_20260721_001/002)。用户诉求:**对标券商研报级研究框架**。
> 核心判断:券商的杀手锏不是单篇报告厚,是**模型常备 + 增量更新**(memory 07-12:"券商调研=事件点评快靠模型常备+增量非人多")。本设计把"厚"建在档案积累上,不建在每日现挖上。

## 用户已拍板(2026-07-22)

1. **四层都要**:L4 决策卡做厚 + 常备覆盖模型 + full 档升首次覆盖级 + 准确度体系(过程级)。
2. **覆盖池进出 = 自动为主 + 手动保送**:持仓/pinned 即入;近 20 交易日 ≥2 次 finalist 自动入;手动点名入;连续 20 交易日未再入选自动退池(档案留存,只停增量维护)。池规模自然浮动 ≈15~30 只。
3. **成本红线 = 每日扫描维持 ~40-50min**:靠档案复用挤质量(池内 L4 只做增量);首覆建档盘后批跑,不占扫描窗口。

## 目标 / 非目标

**目标**:①研究丰富度——卡片底料对标券商(业务拆分/产业链/一致预期对比/公告原文/席位史);②准确度——断言分级带源、价格断言强制对账、SELL 双复核、预测留档对账;③复用——覆盖池内的票不再每天从零 DD。

**非目标**:
- **不改超短 T+2 交易尺**(07-10 用户裁定,勿再推 swing)。券商框架的月级目标价体系不进决策仪表盘;三情景只做**方向框架**(驱动变量+证伪点),不做精确 EPS 预测。
- **stock-deep-analyzer 插件不进管道**(独立生态、产物不机读、不可回放、进不了 t1/retro 对账环);留作用户手动深潜工具。
- 不动 L0-L3 漏斗结构(新闻召回路是正交提案,见 Wave 4)。

## 体系总览

```
                    ┌──────────────── 准确度横切(⑤):断言分级/价格对账/SELL双复核/预测留档/引用密度lint ─────────────┐
                    │                                                                                              │
入池(③池管理) ──→ 首覆建档(②full档升级·盘后批) ──→ 【档案 dossier(①中枢)】 ──→ L4 增量消费(④厚卡·每日扫描) ──→ 变化项回写档案
  持仓/pinned            挂 19:30 prewarm launchd         context/knowledge/dossiers/       注入摘要≤3k + 当日δ
  20日≥2次finalist                                        八节机读结构                       t1/retro 判例自动聚合回档案
  手动点名
```

四个诉求合成一个体系:档案是中枢,首覆是建档动作,厚卡是每日消费,准确度是横切质控。

## ① 中枢:个股档案 dossier

**落点**:`context/knowledge/dossiers/<code>.md`(context/ 已 gitignore)。**格式**:YAML frontmatter 机读头 + 八节 markdown。

```yaml
---
code: "300857"
name: 协创数据
sector: 消费电子          # 申万一级
pool_status: active       # active | retired
entered: 2026-07-22
entry_reason: pinned      # pinned | finalist_2x | manual
initiated: 2026-07-22     # 首覆完成日
last_refresh: 2026-07-22  # 最近全量刷新(中报季强制)
last_delta: 2026-07-22    # 最近 L4 增量回写
summary_tokens: 2800      # 注入摘要的实测 token(≤3000 硬帽)
---
```

**八节**(每节标注数据来源与刷新方式):

| # | 节 | 内容 | 来源 | 刷新 |
|---|---|---|---|---|
| 1 | 业务模型 | 分业务收入/毛利拆分表(近 2 期)、收入驱动公式(量×价/订单/产能)、产业链上下游映射(供应商/客户/竞品→代码) | **tushare `fina_mainbz`(已探通:type=P 分产品含 bz_sales/bz_profit)**+ 年报网查补驱动叙事 | 首覆+中报季 |
| 2 | 盈利驱动+预测留档 | 3~5 个关键驱动变量;三情景**方向框架**(牛/基/熊各自的驱动假设+可观察信号,非 EPS 点估);一致预期快照序列(fwd-EPS/PE 逐次留档) | 同花顺 keyless fwd-EPS(已接)+首覆 agent 判断 | 快照每次 L4 δ 追加;框架中报季 |
| 3 | 估值带 | 历史 PE/PB band(P25/中位/P75,3 年窗)、行业相对位、当前位 | lake 确定性可算 | 确定性,每次 δ 重算 |
| 4 | 筹码资金史 | 户数趋势/解禁日历/质押史/龙虎榜席位史(游资 vs 机构) | 全已有(slim/pledge/calendar/seats) | 每次 δ |
| 5 | 风险矩阵 | CFO/NI 史、审计/监管函史、商誉/减值、大股东行为;每条配**证伪触发点** | slim deep 块 + precedents.db 前科(已有) | 首覆+事件触发 |
| 6 | 催化剂日历 | 未来 60 日带日期事件(财报日/解禁/发布会/政策窗口) | calendar+consensus(已有)+首覆网查 | 每次 δ |
| 7 | 判例账本 | **本系统对它的历史评级 vs 实际**(t1_review 逐笔 + retro 归因聚出;= 券商"覆盖以来记录") | t1/retro ledger 确定性聚合 | 每次 δ 自动 |
| 8 | 变化项日志 | 逐日增量(新公告/资金转向/评级变化),append-only,近 20 条滚动 | L4 卡"档案对账"节回写 | 每次 δ |

**摘要注入契约**:档案头部维护一个 `## 摘要(注入用)` 节 ≤3k token(业务一句话/驱动变量/估值带位置/风险矩阵 top3/未决催化 top3/判例胜率一行)。**维护分工**:叙事部分由首覆 agent 初写、每次 δ 由 L4 回写时同步更新;可机算部分(估值带位置/判例胜率行)由确定性脚本重算覆盖;确定性 lint 把关(≤3k token 帽 + 六项结构锚缺一 warn)。L4 prompt 只注入摘要+按需全文路径。

## ② 建档 = 首覆 workflow(full 档升级)

- **引擎**:`stock-research` full 档(engine-playbook v4:决策主线+证据附录)扩展四节:分业务建模(fina_mainbz)、估值桥(band+相对)、三情景驱动框架、风险矩阵。产出**直接写 dossier 八节**,不再是一次性报告(full 档独立使用时仍出报告,双模式)。
- **编排**:新 `.claude/workflows/dossier-init.js`(单票一 workflow,与 l4-stock 同型:确定性取数(harvest full+mainbz)→ 1 Opus 首覆 agent → 确定性渲染摘要+lint)。
- **调度**:入池未建档 → 进队列(`coverage_pool.json` 的 `pending_init` 列表)。**LLM 段必须在 Claude session 内跑**(本项目零付费 API,launchd 拉不动 workflow):默认在每日扫描收尾(assemble+GATE4 后)由主会话顺手消化 ≤3 只/晚(每只 ~10-20min,不占扫描窗口),或用户任意盘后说「建档」即消化队列;launchd 19:30 prewarm 只承担**确定性预取**(fina_mainbz/fwd-EPS/估值带入湖),为建档省墙钟。扫描时池内无档案的票**降级走现行流程**(presence-gated,不阻塞)。
- **准确度**:首覆产物同样受⑤约束(断言分级/带源/价格对账)。

## ③ 池管理

- **落点**:`context/knowledge/coverage_pool.json`(确定性维护,CLI `python -m autoresearch.dossier.pool`)。
- **进**:pinned/持仓即入(读 pinned.jsonc);`finalists.csv` 滚动 20 交易日**真选**计数 ≥2 自动入(只算 finalist:true 的 L3 真选,pinned 注入行不计——防持仓靠保送自我强化);手动 `pool add <code> --note`。
- **退**:连续 20 交易日未入选 finalist 且非 pinned → `retired`(档案保留,停 δ 维护;再入选自动复活)。
- **prelude 集成**:`scan.prelude` 尾部跑池日检(进出变动打印到当日件建议行),GATE1 后 workflow 可读池清单。

## ④ L4 每日增量模式(厚卡)

- **池内票**(有档案):`l4_card prompts` 生产 `_l4_prompt_<code>.md` 时注入档案摘要(≤3k)+ 当日 δ 素材(今日公告/资金/价格 vs 档案基线);卡内"变化项(vs 档案)"节升级为**"档案对账"**节(驱动变量哪个动了/风险矩阵哪条触发/判例账本一行);P1-P3 表面挖掘对档案已覆盖项**只核对不重写**→ 单卡 token 估 -20~30%。卡尾确定性回写档案第 8 节+重渲摘要。
- **所有卡增强**(丰富度,不依赖档案):公告**原文引句**(intel/网查须引原文一句而非转述标题)、同链对比行(档案产业链映射,池外票用行业 brief 兜底)、一致预期 vs 实际差一行、席位史一行(seats 已有)。
- **情报站聚焦增量**:池内票的 l4-intel prompt 附"档案已知清单"(标题级),查询额度花在增量上。
- **parity**:无档案/池空 → 完全现行为;摘要缺失/超 3k → lint warn + 不注入。

## ⑤ 准确度体系(横切五件)

1. **断言分级**:卡与首覆的关键断言标 `[已核]`(slim/lake 数字)/`[网查:URL+日期]`/`[推断]`;l4-card.md 模板与 engine-playbook 同步加规则("已核数字摘录"节的全卡化)。
2. **价格断言强制对账**:intel/网查中的价格/涨跌幅断言,assemble 侧确定性抽取(正则:日期+涨跌%/价格)与 lake OHLCV 对账,不符 → 卡尾自动附"⚠️价格断言对账失败"行(pr_20260714_006 根治,机制不靠自觉)。
3. **SELL 双复核**:l4-stock.js 的双复核触发条件从 `≥OW` 扩为 `≥OW ∥ (pinned 且 rating∈{Sell,Strong Sell})`(卖错持仓代价不对称;07-21 协创/长飞 SELL 为单 run 产出)。折回规则同现行:取中位、只向保守方向折。
4. **预测留档对账**:档案第 2 节的三情景方向主张 + 一致预期快照,中报披露后跑季度对账 CLI(`dossier.reconcile <period>`),偏差写回风险矩阵;短尺对账仍归 t1/retro,不重复。
5. **引用密度探针**:product_shape_lint 加一探针:满卡带日期引用 <6 行 → warn(07-21 银河微电 4 行的病);早停卡豁免。

## 成本核算(红线 40-50min)

| 项 | 变化 | 依据 |
|---|---|---|
| 池内 L4 卡(估日均 5-8 只) | **-20~30%/卡** | 摘要替代 P1-P3 重复挖掘 |
| intel 全开(修复 config 事故后) | +2-3min 墙钟(与 slim 并行)、+~15k/股 sonnet | 07-14 实测量级 |
| 卡增强(原文引句/对比行) | +5-10%/卡 | 输出增量为主 |
| 首覆建档 | 0(盘后批,不占扫描窗) | 挂 prewarm 时段 |
| **净效果** | **12 卡日 ≈持平或略省,丰富度显著升** | 池内省的 ≥ 增强花的 |

## Parity / 降级 / PIT

- 全链 presence-gated:池空/无档案/摘要缺 → 现行为逐字不变(repo 惯例"全默认关→parity 不破")。
- 档案是 dated staging 产物:L4 注入的摘要以 `last_delta` 为准;回放(replay)读当日落盘的 `_l4_prompt_*`,不受档案后续演化影响(PIT 由 prompt 落稿保证,现机制已有)。
- 降级记账:fina_mainbz 单票拉失败 → 业务拆分节标 `[数据缺,YYYY-MM-DD]`,不空写(数据契约 B 级:降级必须留痕)。

## 分期与验收

- **Wave 1(先落,1-2 天)——准确度横切 + 卡增强**:⑤的 1/2/3/5 + ④的"所有卡增强"。验收:下次真扫描,满卡带日期引用 ≥6 行、价格断言对账 0 失败或有痕、持仓 SELL 出现双复核 `_ensemble` 文件。
- **Wave 2——档案地基**:①schema+渲染器、③池管理+prelude 集成、②首覆 workflow;先对 4 只持仓建档。验收:4 份档案八节齐、摘要 ≤3k、夜批不阻塞扫描。
- **Wave 3——增量接线**:④池内注入+档案对账节+回写、⑦判例聚合、⑤-4 季度对账 CLI。验收:池内卡 token 实测下降、档案第 8 节逐日增长、retro 复盘可引档案。
- **Wave 4(正交,另案)**:新闻召回路影子版(2026-07-21 对话已设计:LLM 只做名称+引句+事件类型,映射/对账全确定性,影子 2-4 周攒 edge 再谈注入)。

## 风险与开放问题

- **档案陈旧**:中报季(4/8/10 月末)强制全量刷新;`last_refresh` 超 90 日 → lint warn。
- **档案污染**:首覆网查内容进档案必须带源(⑤-1);档案被 L4 引用时错误会复利——风险矩阵每条须带证伪触发点,δ 时核对。
- **fina_mainbz 覆盖率**:已探通 300857/601869(分产品 5 行含利润);小票/金融股披露口径可能缺 → 降级留痕(见上)。
- **摘要 3k 帽**:若实测不够(复杂票),Wave 3 再议分层注入(摘要+按维检索),不预建。
- **池峰值**:牛市 finalist 换手加快,池可能涨到 40+ → 退池窗从 20 日收紧到 10 日,池帽 30 只硬截(FIFO by last_selected)。
