## 0. 一页摘要

在不改变任何研究结论的前提下(验收口径 = 用户裁定的「决策级一致」,定义见 §3.1),把项目按三层瘦身:

- **表述层(批 0)**:静态文档与契约文件的冗余表述——skill 文档、10 个 agent 定义、workflow JS 注释、playbook、README、CLAUDE.md、config 注释。主会话与 subagent 每场都要吃,但可缓存,ROI 靠「体积 × 读取次数」。
- **输入层(批 1)**:每场唯一、不可缓存的 agent 输入——slim、`_l4_prompt` 任务包、市场地形。真金白银层:cache 命中率为零。
- **结构层(批 2)**:命令壳合并、死代码删除、learning 目录改名、prelude 并行化。壳是 62% 加权输入的大头。
- **收口(批 3)**:session_v1 转正——壳税归零的根治,指向既有轨道,本稿不重复设计。

**量级(估算,落地以批内实测为准)**:三层全做完,单场加权输入 ~10M → ~4–5M,成本 ~$40 → ~$15–20,墙钟 50–75 → 25–40 分钟。每批独立验收、合入即冻结,不依赖后续批。

## 3. 贯穿约束

### 3.1 「决策级一致」的精确定义

**不变清单**(任何批合入前必须逐项核对):

- 确定性层产物与门结论:GATE1/2/4 全部结论、`run_mode`、守卫 ①–⑩ 行为、E6 决策文件字节(`_relative_buy_decision.json`)、`_final_ratings.json` / `decision_records.json` 的字段与值。
- 报告结构与全部数字:brief/summary/appendix 的节骨架与每个数字;brief 同 run 重放的字节稳定性。
- 契约行:卡片模板行、`**Rating**` / `FINAL TRANSACTION PROPOSAL`、入场行、执行线、情报声明行、`## 地形段` 标题、agent 定义里所有机读字样(「字样勿改」行)。
- 数据契约:入湖字段、A/B 级契约、账本记录。

**可变清单**:卡面与研判的解释性措辞(在模板内)、报告解释性语句、文档表述、注释。

**诚实口径**:LLM 判断层不可逐票重放(同一输入重跑评级本身有噪声),所以批 1 的真实扫描验收 = 结构/门/数字全过 + 评级分布与早停率对照基线无系统性偏移,而不是「同一只票同评级」。此口径写入验收,不假装可复现。

### 3.2 契约唯一真身与「一字不动」清单

- agent 契约唯一真身 = `.claude/agents/*.md`;流程契约 = `SKILL.md` + `STAGES.md`;参数契约 = `scan_config.jsonc`。瘦身只删冗余表述,清单内字样一字不动:l4-card 模板(A/B 卡)、执行线两行、intel 声明行、`TERRAIN_HDR`、五档评级映射、早停七选一、入场三态。
- 升格检查(历史教训):改任何契约文件前后,必跑契约测试并 grep 全部消费者;「绿灯不等于有灯」,删改后用变异测试确认测试有鉴别力。

### 3.3 双引擎

Codex 研究角色读同一份 `.claude/agents/*.md`(手册 §12),表述层瘦身**自动双引擎生效**;`.codex/agents/*.toml`(策略师/行业/L3/L4/复核/壳)每件同步检查一次,保证契约测试两边都锁。

- 09-26 实施期冻结:不新增法证层/普查族 → 本稿全部项目是删减与重排,不新增任何层;批 2 的 6.4 前置(12 步依赖图)是一次性代码审查,不是新法证产物。
